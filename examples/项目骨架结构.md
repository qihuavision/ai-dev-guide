# 项目骨架结构

> 推荐的通用项目目录结构，适用于大多数 Python / CLI / 服务类项目。
> 复制即用，按项目类型增删（见文末"按项目类型调整"）。
> 核心原则：**关注点分离、约定优于配置、文档与代码同仓**。

## 一、推荐目录树

```
project-root/
├── docs/                       # 所有文档集中存放
│   ├── proposal.md             # 立项书（背景/目标/范围/风险）
│   ├── prd.md                  # 产品需求文档 / 需求清单
│   ├── architecture.md         # 架构设计（模块、依赖、数据流）
│   ├── handover.md             # 交接文档（部署/运维/故障处理）
│   ├── security.md             # 安全设计与评审记录
│   ├── testing.md              # 测试计划与用例说明
│   └── adr/                    # 架构决策记录（每条一个文件）
│       ├── 0001-use-postgres.md
│       └── 0002-no-orm.md
│
├── src/                        # 源代码（业务逻辑）
│   └── <package_name>/         # 主包，名同项目
│       ├── __init__.py         # 包初始化、版本号
│       ├── core/               # 核心领域逻辑（不依赖 IO）
│       ├── services/           # 业务服务层（编排 core 与外部）
│       ├── adapters/           # 外部依赖适配（API/DB/MQ 适配器）
│       ├── cli.py              # 命令行入口（CLI 项目）
│       ├── api.py              # HTTP/Web 接口层（服务类项目）
│       └── utils.py            # 通用工具函数
│
├── tests/                      # 测试代码，结构与 src 对应
│   ├── unit/                   # 单元测试
│   ├── integration/            # 集成测试
│   ├── golden/                 # Golden 回归用例（输入+期望输出）
│   │   ├── case_001/
│   │   │   ├── input.json
│   │   │   └── expected.json
│   │   └── case_002/
│   ├── fixtures/               # 测试数据与桩文件
│   └── conftest.py             # pytest 公共夹具
│
├── config/                     # 配置文件（非密钥）
│   ├── default.yaml            # 默认配置
│   ├── dev.yaml                # 开发环境覆盖
│   └── prod.yaml               # 生产环境覆盖（仅结构，值走 Secret）
│
├── scripts/                    # 运维与自动化脚本
│   ├── setup.sh                # 一键安装/初始化
│   ├── run.sh                  # 启动入口
│   ├── test.sh                 # 跑全部测试
│   ├── lint.sh                 # 静态检查
│   └── migrate.py              # 数据迁移脚本（如需要）
│
├── templates/                  # 模板与生成物骨架
│   ├── config.example.env      # 环境变量示例（提交到仓库）
│   ├── email_template.html     # 邮件/通知模板
│   └── report_template.md      # 报告/输出模板
│
├── .github/                    # CI/CD 与协作配置
│   └── workflows/
│       └── ci.yml              # 持续集成流水线
│
├── .gitignore                  # 忽略规则
├── .env.example                # 环境变量示例（不含真实值）
├── README.md                   # 项目入口说明
├── CHANGELOG.md                # 变更日志
├── LICENSE                     # 开源协议（如适用）
├── pyproject.toml              # Python 项目元数据与依赖（推荐）
├── requirements.txt            # 锁定的生产依赖
└── requirements-dev.txt        # 开发/测试依赖
```

## 二、各目录用途速查

| 目录/文件 | 用途 | 必备？ |
|-----------|------|--------|
| `docs/` | 所有人类可读文档，与代码同仓保证不丢失 | 必备 |
| `docs/adr/` | 记录"为什么这么决策"，防止反复推翻 | 强烈推荐 |
| `src/<package>/` | 业务源码，单一主包便于导入与分发 | 必备 |
| `src/.../core/` | 纯领域逻辑，不碰文件/网络/DB，易测试 | 推荐 |
| `src/.../adapters/` | 外部依赖的适配层，隔离 IO，便于替换 | 推荐 |
| `tests/` | 测试与源码同级而非散落，结构镜像 `src` | 必备 |
| `tests/golden/` | 固定"输入→期望输出"，防悄悄改坏结果 | 强烈推荐 |
| `config/` | 环境相关配置，与代码分离 | 视项目 |
| `scripts/` | 一键脚本，把重复手工步骤固化 | 推荐 |
| `templates/` | 配置示例与输出模板，新人照抄即可 | 推荐 |
| `.github/workflows/` | CI 自动化，保证每次提交都自检 | 推荐 |

## 三、按项目类型调整

### 1. Web / API 服务项目（在通用基础上增加）

```
src/<package>/
├── api/                # 路由与请求处理
│   ├── routes.py
│   └── schemas.py      # 请求/响应模型（pydantic）
├── middleware/          # 鉴权、日志、限流等中间件
├── db/                  # 数据库连接、模型、迁移
│   ├── models.py
│   └── migrations/
└── tasks/               # 异步任务 / 定时任务
```
- 增加 `docker/`（Dockerfile、docker-compose.yml）。
- `config/` 中增加 `logging.yaml` 日志配置。
- `tests/` 中增加 `e2e/` 端到端测试目录。

### 2. 纯脚本 / 工具类项目（在通用基础上精简）

- 可省略 `src/<package>/api.py`、`middleware/`、`db/`。
- `core/` 与 `cli.py` 仍是核心，把可复用逻辑放 `core/`，入口放 `cli.py`。
- 可省略 `docs/prd.md`（脚本通常无产品需求），但 `proposal.md` 和 `README.md` 不能少。
- 单文件脚本（< 300 行）可直接放根目录 `main.py`，但仍建议保留 `README.md` 与 `tests/`。

### 3. CLI 工具项目

- 入口集中在 `src/<package>/cli.py`，用 `click` / `typer` / `argparse` 组织子命令。
- `pyproject.toml` 中配置 `[project.scripts]` 以支持安装后全局命令调用。
- `templates/` 用于存放命令输出模板（如生成代码、报告）。

### 4. 数据 / ETL 项目

- 增加 `pipelines/`（数据处理流水线定义）。
- 增加 `data/`（仅放小样本数据，大数据走外部存储并在 `.gitignore` 忽略）。
- 增加 `notebooks/`（探索性分析，加 `.gitignore` 忽略输出）。
- `tests/golden/` 尤为重要，用于固化数据转换的期望结果。

## 四、`.gitignore` 关键项建议

以下内容建议加入根目录 `.gitignore`，避免把不该进库的东西提交上去：

```gitignore
# === 密钥与机密（最高优先级，绝不上库）===
.env
.env.*
*.pem
*.key
secrets/
credentials.*

# === Python ===
__pycache__/
*.py[cod]
*.egg-info/
.eggs/
build/
dist/
.venv/
venv/
.pytest_cache/
.mypy_cache/
.ruff_cache/
.coverage
htmlcov/

# === 虚拟环境与依赖目录 ===
node_modules/

# === 编辑器与系统 ===
.vscode/
.idea/
.DS_Store
Thumbs.db

# === 数据与日志（按需）===
data/raw/
data/processed/
logs/
*.log

# === 构建产物 ===
*.lock.db
*.tmp
```

**特别提醒**：
- `.env` 必须被忽略，而 `.env.example` 必须上库——前者含真实密钥，后者只含键名占位。
- `data/` 下只提交小样本或 schema，大数据文件走外部存储。
- 首次提交前先建好 `.gitignore`，否则一旦密钥/缓存进库，清理历史成本极高。

---

**使用建议**：立项后第一时间按本骨架建出空目录与占位文件，再逐步填充。
目录先于代码存在，能避免"代码写完才发现没地方放"的混乱。
