# AI 开发规范 (ai-dev-guide)

> 一套**通用的、项目无关**的 AI 协作开发方法论、模板与检查清单。
> 任何项目开工前，让 AI 先读本库，再开始讨论需求。

## 为什么需要这个库？

AI 协作开发最大的失败模式不是"AI 写不出代码"，而是 **"范围蔓延 + 上下文丢失 + 风格漂移"**：

- AI 不知道边界，越写越大，最后失控
- 每次新会话，AI 重新设计架构，代码风格不一致
- 写到一半，换一个 AI 会话就接不上

本库把这些年沉淀的方法论**固化成文档 + 模板 + 检查清单**，让任何项目都能用同一套规范推进，把上面三个问题结构性解决掉。

---

## 核心理念（三句话）

1. **先定义"不做什么"，再定义"做什么"** —— 护栏比方向更重要。
2. **文档驱动开发** —— 立项书 / PRD / 架构 / 交接文档，每一步都先有文档再写代码。
3. **小步快照、可验证推进** —— 一次一个功能点，每个功能点能跑通、能 commit、能回滚。

## 如何使用本库（三种用法）

### 用法 1：最轻量 —— 只读方法论

开新项目前，把 [`docs/01-AI协作开发方法论.md`](docs/01-AI协作开发方法论.md) 发给 AI，让它按这套方法论推进。

### 用法 2：标准用法 —— 复制模板（推荐 ✅）

1. 把 `templates/` 整个目录复制到你的新项目下（通常是 `docs/`）
2. 在项目根放一份 `AGENTS.md`（见模板），AI 会自动读取
3. 开新会话时，用 `templates/ai-session-prompt.md` 作为开场白
4. 每个阶段对照 `checklists/` 打勾

### 用法 3：最完整 —— 全套引用

在你的项目立项书里写明"本项目遵循 [ai-dev-guide](https://github.com/qihuavision/ai-dev-guide) 规范"，然后让 AI 把本库的文档读一遍再开工。
