## 一、本项目遵循的协作规范

本项目遵循 **[ai-dev-guide](https://github.com/qihuavision/ai-dev-guide)** 规范进行 AI 协作开发。

核心原则：
1. **文档先行**：开工前必读指定文档，不读文档不写代码。
2. **小步快跑**：一次会话只做一个明确功能点，做完即停。
3. **先测后写**：先写测试，再写实现，最后跑通验证。
4. **即时交接**：每次会话结束必须更新交接文档。
5. **不做清单优先**：所有"不做"的边界，比"要做"的更重要。

## 五、提交规范

### 分支命名

```
[类型]/[简短描述]
```

类型：`feat`（新功能）/ `fix`（修复）/ `refactor`（重构）/ `docs`（文档）/ `test`（测试）/ `chore`（杂项）

例：`feat/ticket-export`、`fix/login-redirect`

### 提交信息（Commit Message）

遵循 **Conventional Commits**：

```
<type>(<scope>): <subject>

<body 可选>

<footer 可选，如关联 issue>
```

- `type`：feat / fix / refactor / docs / test / chore / perf
- `scope`：影响的模块，例如 `ticket`、`auth`
- `subject`：祈使句、现在时、不超过 50 字符、结尾不加句号

示例：
```
feat(ticket): 支持工单批量导出为 Excel
fix(auth): 修复 token 过期后未跳转登录页的问题
docs(handover): 更新交接文档，补充已知坑
```

### 提交粒度

- 一个提交只做一件事。
- 不要把"格式化代码"和"修 bug"混在一个提交里。
